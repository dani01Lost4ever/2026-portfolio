# Portfolio

Personal developer portfolio built with React, TypeScript, and a scroll-driven three.js particle field ("Field") — backed by PocketBase as a headless CMS.

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | React 19, TypeScript, Vite |
| 3D | three.js with custom (hand-written GLSL) shaders — no React Three Fiber / drei / postprocessing |
| Scroll animation | GSAP + ScrollTrigger, Lenis smooth scroll — no Framer Motion |
| Backend / CMS | PocketBase |
| Routing | React Router v7 |
| Styling | CSS |
| Containerization | Docker, Nginx |

## Project Structure

```
│   ├── data/              # Static JSON seed data
│   ├── lib/

│   │   └── projectVisuals.ts  # Resolves each project's field shape / tech-cube layers / caption / tint
│   └── main.tsx
├── backend/
│   ├── Dockerfile        # PocketBase Docker image
│   ├── pb_data/          # PocketBase database (gitignored)
│   └── pb_migrations/    # PocketBase schema migrations
├── scripts/
│   ├── seed.mjs          # Seed PocketBase from data/ JSON files

├── docker-compose.yml    # Runs frontend + pocketbase together

```

## How the page animation works

The whole page sits on top of one fixed, full-screen three.js canvas (`FieldCanvas`) driven by a
single controller (`FieldController`, mounted via `<FieldProvider>`). React never touches three.js
directly — each section just marks itself up as a "stop" with `data-field-stop` and a few sibling
`data-*` attributes (see `src/field/contract.ts`). The controller reads those attributes, measures
the stops' positions, and maps scroll position to a continuous progress value across all stops.
On every frame it morphs a single 10k-point cloud between the current and next stop's shape,
generated by a per-`ShapeId` function in `src/field/engine/shapes/`, and writes the page's
background gradient to CSS variables so the body gradient tracks the field.

Scrolling itself is smoothed by Lenis, synced to GSAP's ScrollTrigger (`src/field/smoothScroll.ts`);
in-page anchor links are intercepted and eased to their target with the fixed nav's height as an
offset. Under `prefers-reduced-motion` or when WebGL2 isn't available, the field falls back to a
static page: no canvas, no smoothing, instant jumps.

Each project also gets a small isometric "tech cube" (`src/field/techcube/`) that turns through its
four architecture layers as it scrolls through view — a standalone, dependency-free animation
driven by the same scroll progress, not three.js.

See `docs/frontend.md` for the full architecture, and `designs/field.html` for the original
prototype the implementation is ported from.

## Local Development

### Prerequisites

- Node.js 20+
- The `backend/pocketbase.exe` binary (Windows) — download from [pocketbase.io](https://pocketbase.io/docs/)

### Setup

```bash
npm install
```

### Run (frontend + backend together)

```bash
npm start
```

This runs PocketBase on `http://127.0.0.1:8090` and the Vite dev server concurrently.

### Run separately

```bash
# Backend only
npm run pb

# Frontend only
npm run dev
```

### Seed the database

After starting PocketBase for the first time, seed it with the content from `src/data/`:

```bash
npm run seed
```

If collection access rules need resetting:

```bash
npm run fix-rules
```

### Create a PocketBase admin

```bash
npm run pb:admin
```

## Docker

### Start

```bash
npm run docker:up
# or
docker compose up --build
```

This starts two services:
- `pocketbase` — PocketBase API on port `8099`
- `frontend` — Nginx serving the built React app on port `809`

### Stop

```bash
npm run docker:down
```

### Logs

```bash
npm run docker:logs
```

### Build & Push

```bash
npm run docker:publish
```

## Environment Variables

The frontend resolves the PocketBase URL from the first non-empty value of:

1. **Runtime** — `window._env_.PB_URL`, written by `entrypoint.sh` at container startup from the `PB_URL` environment variable
2. **Build-time** — the `VITE_PB_URL` build arg / `.env` variable
3. **Fallback** — `http://127.0.0.1:8090` in dev; the same origin in production builds

In the Docker images, nginx proxies `/api/` and `/_/` (admin UI) to the `pocketbase` service, so leaving `PB_URL` empty serves the site and PocketBase from one domain. Set it only when PocketBase lives on a separate host:

```yaml
frontend:
  environment:
    PB_URL: "https://your-pocketbase-host.example.com"
```
